01 / NAVIGATION BUDDY · PRODUCT JUDGMENT SEC 02 // 03

从「最快路线」到「懂我的路线」

产品判断 我给导航 Agent 拟定的四条判断，每一条都写进了代码里
01 · 效用 ≠ ETA 感知代价折算
最快的不一定是最好的。耗时之外，波动、转向次数、信号灯、过路费全部折算成等价分钟参与排序，不同维度才能直接比较大小。
02 · 偏好是软约束 阈值即额度
「晚 5 分钟」直接变成一个阈值额度：绕开的代价在额度以内就绕行，超出额度就不强制绕行，把原因说明白，再给一个「提到 10 分钟」的一键按钮。
03 · 记忆可见可控可溯源可删 透明控制台
每条偏好都留着你的原话、时间、来源场景、置信度和应用次数。阈值可以拖动，偏好可以暂停、可以删除，每一步都有流水可以查看。
04 · 解释先于惊喜 额度尺审计
改推荐之前先展示解析卡片，改的时候给出新旧对比、额度尺和逐项折算明细，被否决的方案为什么被否决，也写得清清楚楚。

PROJECT 02 // 留乘智行 · 需求响应公交智能调度系统 [40.7831° N, 73.9712° W]

路网建模与寻路机制重构 OSM Graph Topology & Edge-level Cost Evaluation

01 / 三层图拓扑建模 OSM 拓扑
我用 OSM 数据搭建了三层图：物理路网、路由图、调度图，一共 558 个核心站点、16,740 条边。把纽约曼哈顿 270 万条真实订单放上去跑，99.88% 的需求都接得住。
02 / 边级综合代价评估 代价重构
常规调度每一步只需要选择下一个节点，我把决策改成评估整条候选路的综合代价：绕行代价和流失风险都编码成边特征，由边级 Q 值输出下一跳。
03 / 强化学习与连续约束 连续惩罚项
时空图神经网络负责聚合路网动态；车辆容量、乘客最长等待这些硬约束，我改写成连续惩罚项放进目标函数，高并发下训练依然稳定收敛。
从「选择下一个节点」到「评估每条候选路」，这个决策视角和导航 Agent 给路线排序是一脉相承的。
看验证数据与消融实验 查看 GitHub 源码

产品判断：AI 写代码已经不稀罕，稀罕的是人能看懂、能盯住它写了什么。
01 · 需求理解与结构化委派 意图解析
你和角色把需求聊清楚，她把任务整理成带环境边界和产物的结构化委派，交给编程 Agent 去执行。
02 · 本地真实执行与证据回传 审视追问
Agent 在本地项目里真实修改文件、执行命令，改了什么、测试过没过都回传到同一条会话里，角色看完接着追问。
03 · 声音复刻与全双工链路 VAD 聆听
可以按键说话，也可以开着 VAD 直接开口；ASR→LLM→TTS 全链路打通，音色按角色复刻，念出来的就是她自己的声音。
04 · 文件沙箱与高危拦截 确定性拦截
沙箱和高危命令审批交给确定性代码执行，越界操作直接拦截，不指望模型自觉；Key 用自己的，服务器成本为零。
